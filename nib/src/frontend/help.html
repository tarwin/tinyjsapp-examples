Nib

A small, fast Markdown editor — built for folders of documentation.

Introduction

Nib is made for the folders of Markdown that documentation is built from — the content directories behind VitePress, Docusaurus, MkDocs, Astro Starlight, mdBook, Docsify, GitBook and their kin. You open the folder, not just a file: its documents get a tree, tabs, Open Quickly (⌘P) and folder-wide find & replace, and Nib renders what those systems render — the ::: callouts and tabs, GitHub-style alerts, front-matter shown as a quiet block rather than mangled, math to native MathML, ```mermaid diagrams themed to match your preview, footnotes and emoji shortcodes — each of them a toggle under Preview ▸ Markdown Flavor, so the preview can match what your generator will actually do with the file.

Linking is the point of a docs folder, so it gets the most care. Type @ anywhere and the project comes up under the caret; a picked file is linked by its real name — its front-matter title: or first heading — with a path relative to the document. Step into a file with ⇥ to link a section (guide.md#installing, followed links scroll to it), or search the headings themselves — @instal finds “Installing” wherever it lives. Format ▸ Link Options decides whether a section link carries its whole trail (Setup › Alerts › SMS) and how paths are written: relative, /from the folder root, or /from a pinned folder.

Pinning is how Nib stays sane in a big tree — and how it handles translated docs. Right-click a folder, pin it, and ⌘P, the @ picker and Find in Folder see only that subtree; pin en/ and fr/ and each language searches only itself, because the closest pin above the document you’re in answers for it. A pin can cover everything, Markdown only, or pictures only — so assets/ can serve images to every language — and with Paths from the Pinned Folder on, a document in en/ writes /sms/index.md for en/sms/index.md, the way language-rooted sites expect, and such links still open, preview and survive renames inside Nib.

You don’t have to think in Markdown to work here. With ✎ Editable on (⌘⇧L) the rendered page takes the caret: type into it, select for a formatting bubble, tick checkboxes, paste pictures — every pause is written back out as clean Markdown, and in Split view you can watch it happen. The Markdown file is always the document; the preview is a second way in, for the reviewer, the translator, or anyone who just wants to fix a sentence.

Settings live where they belong. How a folder should read — theme, view, flavor toggles, pins, link options — is kept in .nib/settings.json inside the folder, so it travels with the repo and the whole team sees the docs the same way. The file is created only when you change something, you can edit it as an ordinary tab (File ▸ Edit Folder Settings… — saving applies it on the spot), and File ▸ Save Settings in Folder turns the whole thing off, at which point Nib never reads or writes anything inside your folder. What is this machine’s business alone — open tabs, sidebar widths, a parked set of pins — stays in local state, out of the repo.

The formatting reference is a document, not a page: every construct Nib renders — headings to callouts, tabs to math — lives in the example file, real and editable.

Working in a folder

File ▸ Open Folder… (⌥⌘O) puts a project behind the windows: its files appear in a tree down the left of every document window (⌘⇧B to hide it), and clicking one opens it as a tab in that window — one window, many documents, with a strip along the top once there are two. With no folder open, that same panel is where you pick one. One folder at a time, and the folders you’ve opened are listed under File ▸ Open Recent and on the Welcome screen (⌘0), which steps aside while you have a document open.

Pin a folder for search (right-click it in the tree) and ⌘P, the @ picker and Find in Folder are scoped to it instead of the whole project. The 📌 badge on the row is the control: each click narrows what it covers — everything, Markdown only, pictures only — and the last click takes it off. With several pins, the closest one above the document you’re in answers for it; a document under no pin sees all the pinned folders of the right kind together. The palettes and the results panel name the scope they searched. The 📌 at the top of the folder view turns the pins off and on as a set — they keep their places, they just stop scoping — and the 👁 beside it is View ▸ Show All Files in Folder within reach. A pin can also anchor link paths: with Format ▸ Link Options ▸ Paths from the Pinned Folder, a document inside a pinned en/ links en/sms/index.md as /sms/index.md — and such links resolve against the pin when followed, previewed or re-aimed by a rename. Pins are kept in .nib/settings.json so they travel with the folder (with Save Settings in Folder off they stay in this machine’s local state instead); the master switch is always local.

File ▸ Edit Folder Settings… opens .nib/settings.json itself as a tab — .json files open as plain source, previewed as a highlighted code block. Saving the tab applies it on the spot, and changes made from the menus flow back into a clean open settings tab, so the file and the app can’t drift apart.

A project keeps its own look — theme, view mode and the reading options below — in .nib/settings.json inside the folder, so a set of documents can read the way that set should read without redecorating the app. The directory is only created when you actually change a setting, and File ▸ Save Settings in Folder turns the whole thing off: with it unticked Nib never reads or writes anything inside your folder.

  • Hidden files, node_modules, .git, dist and the usual build folders are skipped.
  • Markdown, text and pictures open in a tab — a picture gets a viewer (fit or actual size, with its dimensions and file size) instead of the two panes, and renames from the same ⏎. Anything else is there to be linked to.
  • Renaming moves the open tab, its unsaved draft and its place in your recents with it — and then offers to re-aim the links that pointed at the old name, listing the documents they are in first. Pictures count as much as documents, a renamed folder carries its whole subtree, and a link is matched by where it resolves, so an unrelated file of the same name elsewhere is never touched.
  • Right-click a picture — or a folder of them — and Optimize Picture… squeezes it where it sits: the preview is the re-encode, split against the original under a draggable divider, and once the first one looks right the rest can run the same settings without stopping again. Converting the format renames the file and the links question above is asked once, over the lot. And what a pasted picture is called can be a template — {doc}-{heading}, {pin}, {date} and friends, in Format ▸ Image & Path Settings…

Find and replace

⌘F opens a bar over the document — not a dialog, so the text stays where it is. ⏎ and ⇧⏎ step through the matches (so do ⌘G and ⇧⌘G from anywhere), every match is highlighted at once with the current one picked out, and the count beside the field says where you are. ⌥⌘F unfolds Replace underneath; ⏎ replaces the one you’re on and ⌘⏎ replaces them all. Both go through the editor’s own undo, so ⌘Z takes a Replace All back in one step.

Aamatch case
|ab|whole words only
.*regular expression — a real one: groups, anchors, \b. ^ and $ are line anchors, and the replacement can use $1. A pattern that doesn’t compile says so instead of quietly finding nothing
In Folder · ⌘⇧Fthe same query over every text file in the project, with its own Replace All

Searching a folder has no index behind it and doesn’t need one — the files are read and scanned when you ask, several at a time. Replacing across a folder writes to disk after asking; any file with unsaved changes is skipped and named, because replacing under a buffer you’re editing would lose the edit.

Editable preview

With ✎ Editable on (⌘⇧L, any view but Editor Only) the rendered page takes a caret: type, select, ⌘B, tick a checkbox, paste a picture. Every pause writes the page back out as Markdown, so in Split you can work from either side.

Markdown still works while you type — these turn into the real thing the moment you finish them:

## a heading, one # per level
- a bullet list — then [ ] makes it a task
1. a numbered list
> a blockquote
---then Return — a horizontal rule
`code`a code span
**bold** *italic* ~~struck~~the obvious
[label](url)a link

Select anything and a small format bubble appears above it — bold, italic, strikethrough, code, link, heading levels, quote, list.

Paste a URL over selected text and the text becomes the link’s label rather than being replaced — the docs plus a paste gives you [the docs](https://…), in either pane. It only does this for something plainly a URL over something plainly a label: pasting onto a selection that is itself a URL, or onto the address inside an existing link, replaces it as usual.

This works without Editable too — select text in a plain preview and the matching Markdown highlights in the source pane. Whichever pane holds the cursor, the other one shows where you are — to the character. Select **a phrase** in the source and exactly that phrase highlights in the preview (without its asterisks); select in the preview and the matching Markdown highlights in the source. A caret shows up as a thin blinking bar in the other pane, and if the position is inside a closed tab or a folded ::: details, that opens to show you. Scrolling is anchored the same way — by block, not by percentage, so a tall code fence or a hidden tab panel can’t make the two panes drift apart.

  • Round-tripping normalizes: bullets come back as -, bold as **…**, italic as *…*, tables with even pipes — whatever you originally typed.
  • Anything the renderer can’t show can’t survive the trip back. Keep unusual source (HTML you want preserved verbatim, hand-aligned tables) for the editor pane.
  • The Markdown file is still the document; the preview is a second way in.

Actions

An action is a button that runs something — the build, the deploy, a formatter, the shell one-liner living in your terminal history. They sit under the ⚡ in the toolbar, in the Actions menu, and on a file’s right-click in the tree, which runs them on the file you clicked. Actions ▸ Manage Actions… (⌥⌘A) is where you make one: a list on the left, its settings on the right, nothing written until you press Save.

They come from two files, and the difference is the whole design. Your actions live with Nib’s settings and follow you into every folder. A folder’s actions live in its .nib/actions.json and travel with it — clone a repo and its buttons come along, written by somebody else. So a folder’s action is inert until you approve it, one at a time, in a sheet showing the real command with the variables already filled in and the directory it will run in. Always Allow is pinned to what the action does: rename the button and nothing asks again; change the command and the prompt comes back saying so.

Commandtyped as you would in a terminal — the split into arguments is shown underneath as you go, so echo "hello there" being two arguments is something you can see. Tick run through a shell for pipes and &&
Scriptthe other kind: JavaScript, run in Nib’s backend with ctx.file, ctx.sel, ctx.read/write/list, ctx.run([…]). Return a string and it becomes the output
Available whenalways, or only with a folder open, a saved file, a selection — and only for files like *.md. A button that can’t run greys out and says why
Readsnothing, or the document or selection piped in
What it printsthe panel under the document, or it replaces the document (a formatter), goes in at the caret, opens as a new document, or just a notification
Runs inthe pinned folder by default, else the folder, else the document’s own directory

Variables reach everything Nib knows about where you are: {file} {dir} {root} {rel} {name} {stem} {ext} {pin} {sel} {line} {heading} {date}. Output streams into a drawer under the document with a Stop button and the exit code; a run that fails opens it whichever way you asked the output to go. And a command is looked for in the places things actually live (/opt/homebrew/bin, ~/.local/bin and friends), because an app launched from the Dock inherits almost no PATH — a missing one says not found on the button rather than failing when pressed.

Not supported

Markdown has grown a lot of dialects. Nib keeps to the everyday set; these are the notable absences — the example document shows everything that is there.

  • Reference links and reference images ([a][1] … [1]: url)
  • Definition lists, abbreviations
  • Setext headings (=== / --- underlines)
  • Inline HTML — always shown as text, never rendered
  • Front-matter is shown, not interpreted — Nib never edits or hides your metadata
Preview ▸ Markdown Flavor holds the extras, each its own toggle with GitHub / CommonMark presets: alerts (> [!NOTE]), math ($x$, $$…$$, ```math — rendered to native MathML), ```mermaid diagrams themed to match the preview, emoji shortcodes (:tada: 🎉), and footnotes ([^1]). The shows them all live.

About Nib

Nib

A small Markdown editor by tarwin, built as a tinyjs example. Everything you see — the Markdown renderer, the syntax colours, undo, the emoji picker — is Nib’s own plain JavaScript, no libraries. What it stands on deserves the credit:

  • tinyjs — the tiny desktop-app framework Nib runs on: native windows, menus, dialogs and the bridge between them.
  • txiki.js by Saúl Ibarra Corretgé (MIT) — the JavaScript runtime behind Nib’s backend, itself built on QuickJS-ng (from Fabrice Bellard’s QuickJS) and libuv.
  • The system webview — WebKit (WKWebView on macOS, WebKitGTK on Linux) draws every window; no browser is bundled.
  • Markdown — John Gruber and Aaron Swartz’s design, “a text-to-HTML conversion tool for web writers”; Nib keeps to the everyday set as CommonMark and GitHub Flavored Markdown spell it.
  • Emoji are plain Unicode characters, drawn by the system.
